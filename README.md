# Dynamic Airport Parking

Park at the shop, shuttle to PVU, service cars while customers are away. A service of Dynamic Collision Repair.

Static site on Firebase Hosting, with customer accounts (Firebase Auth), bookings (Firestore) and a floating payment window (Stripe + PayPal through Cloud Functions).

## Pages

| Page | What it does |
|---|---|
| `index`, `how-it-works`, `pricing`, `faq`, `contact`, `terms` | Brochure pages |
| `register` | Creates the login and writes the customer to `customers/{uid}` |
| `login` | Email + password, forgot-password |
| `account` | Profile, saved vehicles, bookings, **Pay now**, cancellation request |
| `reserve` | Logged-in booking form with live price estimate, then the payment window |

Artwork in `assets/img/*.svg` is generated by `tools/make_art.py`. Swap in real photos any time (keep the file names or edit the `<img>` tags).

## One file holds the business details

`assets/js/config.js` has phone, address, prices, shuttle details, Firebase config and public payment keys. Anything left `null` shows as a yellow **TBD** on the page.

## Go-live checklist

1. **Firebase console** (project `dynamicairportparking`)
   - Build → Authentication → Get started → enable **Email/Password**
   - Build → Firestore Database → create
   - Project settings → Your apps → add a Web app → paste its config into `FIREBASE_CONFIG` in `config.js`
   - Authentication → Settings → Authorized domains: add your live domain
2. **Prices (optional, editable without code):** create the Firestore doc `settings/pricing` with `perDay` (number) and `perWeek` (number or null). It overrides `config.js` and is the number the server charges.
3. **Deploy** hosting + rules:
   ```
   npm i -g firebase-tools
   firebase login
   firebase deploy --only hosting,firestore
   ```
4. **Payments** (Cloud Functions need the Blaze pay-as-you-go plan; it's usage-based and tiny at this volume)
   - **Stripe** (card + Cash App Pay): create an account, turn on Cash App Pay under Settings → Payment methods. Put the *publishable* key in `PAYMENTS.stripePublishableKey`. Then:
     ```
     firebase functions:secrets:set STRIPE_SECRET_KEY
     firebase functions:secrets:set STRIPE_WEBHOOK_SECRET
     ```
     Add a Stripe webhook pointing to the deployed `stripeWebhook` URL, event `payment_intent.succeeded`.
   - **PayPal + Venmo**: create a REST app at developer.paypal.com, put the client ID in `PAYMENTS.paypalClientId`, then:
     ```
     firebase functions:secrets:set PAYPAL_CLIENT_ID
     firebase functions:secrets:set PAYPAL_CLIENT_SECRET
     ```
     Functions default to the PayPal sandbox. Set `PAYPAL_ENV=live` when you're ready for real money. Venmo appears on eligible US mobile devices; enable it in your PayPal business account.
   - `cd functions && npm install`, then `firebase deploy --only functions`
5. Test with Stripe/PayPal **test** keys first.

## How money and data are protected

- Card numbers never touch this site. Stripe and PayPal render their own secure fields.
- The browser never sets the price. `getPaymentQuote`, `createPaymentIntent` and `createPayPalOrder` compute it on the server from the booking's dates and `settings/pricing`; PayPal captures are re-checked against the booking and amount.
- Customers can read only their own profile, vehicles, bookings and receipts. They can create unpaid bookings and request a cancellation, nothing else. Payment records and `paid` status are written only by Cloud Functions.
